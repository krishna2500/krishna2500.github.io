Verify USDT payments automatically with TronGrid (free, no API key)

If you're accepting USDT directly to your own wallet, you don't need a payment gateway at all — you need a watcher: something that reads the chain, matches an incoming transfer to an order, and marks it paid. TronGrid's public endpoint does the reading for free.

1. The endpoint

List recent USDT transfers TO your address — no API key, no signup:

GET https://api.trongrid.io/v1/accounts/{YOUR_ADDRESS}/transactions/trc20
    ?only_to=true&limit=50

Response items carry transaction_id, value (in 6-decimal base units), block_timestamp, from and a token_info.address you should verify against the official USDT contract:

TR7NHqjeKQxGTCi8q8ZY4pL8otSzgjLj6t

2. Matching transfers to orders

const value = Number(tx.value);            // e.g. 5007291
const amount = (value / 1e6).toFixed(6);   // "5.007291"
const match = pending.find(o =>
  o.amount === amount && o.created <= tx.block_timestamp
);
if (match && !(await seen.get(`seen:${tx.transaction_id}`))) {
  match.status = "paid";
  await seen.put(`seen:${tx.transaction_id}`, match.id);
}

Two rules make this safe:

GuardWhy
Unique amount per order (price + random(1000..9999)/1e6)Two pending $5 orders would otherwise both match "5.000000". The suffix is your order ID, embedded in the amount.
seen:<tx_id> single-use storeThe same transfer must never pay two orders, even if a watcher crashes mid-loop.

3. Run it on a cron

Once a minute is plenty for checkout flows — TRON blocks land in ~3s, but buyers tolerate a minute. A Cloudflare Worker with a * * * * * trigger, a KV namespace for orders/seen-tx, and this loop is the entire backend. No server, no database, no fees, and the money never touches a third party.

Want the whole thing pre-built? usdt-paykit (open source) ships the watcher, exact-amount invoice logic and Telegram alerts — or grab the full worker source from the shop ($5 USDT Integration Kit, verified on-chain like everything else).
